04 Voiceover

Three routes, best-sounding first. All three end with the same post chain and a beat-map so consonants land on the music.

A. Your own voice + free cleanup recommended

A real founder voice reading a case file beats any TTS for a documentary brand — and it's the one thing competitors can't copy. Record on a phone in a quiet room (or a $30 lav mic), then run the free chain below.

  • Record: Audacity (free, MIT-ish) or your phone's voice memo. One take per scene, plus 5 seconds of silent "room tone".
  • Clean (Audacity, all built-in): Noise Reduction (sample the room tone) → High-pass 80 Hz → gentle EQ presence bump +3 dB around 4 kHz → De-esser → Compressor 3:1, −18 dB threshold → Limiter −1 dB → Loudness Normalize to −16 LUFS.
  • Cost: $0. Time: ~20 min per reel once the chain is saved as a macro.
Fallback if the room is noisy: record the same take and also generate option B, pick per-line.

B. Local neural TTS — free & commercial-safe

  • Kokoro-82M (Apache-2.0) — currently the best open TTS for its size; near-ElevenLabs on clean reads, runs on CPU at ~real-time, ~350 MB. Commercial use allowed, no attribution.
  • Piper (MIT) — lighter, very fast, a notch below Kokoro; good for scratch tracks.
  • Both install locally, no key, no quota. I can wire either into the existing narrate.py pipeline.
This is the straight upgrade from edge-tts Andrew at zero cost.

C. ElevenLabs — $5/mo (not free, but negligible)

  • Free tier = 10k credits/mo (~10 min) but no commercial rights (attribution required) — fine for testing only.
  • Starter $5/mo = 30k credits + full commercial licence + voice cloning (clone your own voice once, generate forever).
  • OpenChatCut already has an ELEVENLABS_API_KEY slot — drop the key in and it's a menu option in the editor.
The pragmatic pick if you don't want to record. Sources: elevenlabs.io/pricing, smallest.ai, bigvu.tv.

"Accurate drops" — the beat-map

This is what makes Greg's edits feel tight: cuts, word reveals and SFX land on the music's transients, not on round seconds. Method: pick the bed first → detect its onsets (librosa / aubio, free) → export a frame list → snap every scene cut and every kinetic-word reveal to the nearest onset → SFX ride the same grid. I can automate this end-to-end from a chosen bed.

05 Production approach

Tier A — Upgrade the current pipeline do now · $0

Stay in HTML/CSS/GSAP (renders reliably here), but rebuild the visual layer to the product system. Gets ~70% of Greg's polish without a new tool.

  • Retokenise to §03 palette + Anton/Newsreader/Caveat/Inter.
  • Build a reusable LexIntent Motion Kit: kinetic-word component (Anton, VO-synced), signal-meter gauge, red-pen circle (Caveat + rough SVG stroke), rubber-stamp thud, dashed-rule divider, hard-shadow paper card, 2–3 layer parallax stack.
  • Rebuild Case File 001 on the kit: real paper texture at full strength, cast shadows, 7-second recruiter-scan bar, signal meter that visualises weak vs strong lines, side-by-side rewrite reveal, camera push on every scene, cut rhythm 1.2–1.8s.
  • Beat-map to a chosen bed; new voice from §04.
Effort: ~1 build day for the kit, then ~2–3 hrs per reel. This is the recommended next move.

Tier B — True 3D depth phase 2

  • Blender (free) — a small reusable scene kit (paper planes, desk, stamp, meter) rendered with real light + DoF, composited over the HTML type layer. This is how you actually match Greg.
  • Or Jitter Pro (~$16/mo) / Cavalry (free tier) — browser/desktop motion tools with real 3D, far faster than Blender for this style.
  • Blocked today by RAM/time; revisit once the machine has headroom or on a cloud render box.
Do this only after Tier A ships 2–3 reels and the format is proven.

Tier C — Buy the look optional

  • Adapt a premium editorial-motion template (Jitter community, Envato) to the brand tokens. Fastest path to a Greg-tier frame; least control; small one-off cost.
