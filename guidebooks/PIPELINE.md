# ai-agency Reel Pipeline — Complete Technical SOP

This is the exact, reproducible pipeline used to build every `ai-agency` demo
reel (flagship: `demos/ep-001-inbox-to-crm`). It is written so **any AI
assistant** (Claude, Antigravity, GPT, etc.) with shell + ffmpeg + Python
access can pick this up cold and produce an episode to the same standard,
with no prior conversation context required.

Read alongside:
- `DESIGN_PHILOSOPHY.md` — why the pipeline is shaped this way (brand rules,
  pacing rules, what NOT to do, with real failure examples).
- `GEMINI_ASSET_AUTOMATION.md` — how the photoreal hero-shot assets get made.
- `QC_CHECKLIST.md` — the exact checklist to run before calling an episode done.

---

## 0. Prerequisites

- **ffmpeg / ffprobe** — path hardcoded at the top of every build script
  (`D:\tools\ffmpeg\ffmpeg-8.1.2-essentials_build\bin\`). Update if it moves.
- **Python 3** — invoked as `py -3` on Windows (NOT `python3`). All pipeline
  scripts are pure-stdlib + a few small deps (`faster-whisper`, `Pillow`).
- **opencli** — a Browser Bridge CLI controlling the user's real, already
  logged-in Chrome (two profiles: `ygnt53g4` default/images, `whghbej8`
  video). Windows `.cmd`, so any `subprocess.run` call needs `shell=True`.
- **Fonts**: system Arial/Arial Bold for UI text; `Caveat` and other Google
  fonts live in `assets/fonts/google/` for hand-written annotation styling.
- **Installed Claude Code skills** (global, `~/.claude/skills/`): `video`,
  `image` (from smixs/visual-skills — cinematography/art-direction
  reference), and `01-viral-hook` through `10-podcast-visual` (Seedance 2.0
  prompt-engineering patterns, from rediumvex/ai-video-generator-claude).
  Load the relevant one before writing any new Gemini prompt or auditing a
  cut — see `DESIGN_PHILOSOPHY.md` for which skill maps to which beat.

## 1. Folder structure (per episode)

```
ai-agency/demos/<episode-slug>/
  narration/
    narration.json        # script: cues with {id, at, window, text}
    vo.mp3                 # generated VO (or recorded)
    vo-v1-backup.mp3        # keep every prior VO cut, never overwrite silently
  evidence/
    <name>.html             # real UI mockups, screenshotted then cropped
    <name>-crop.png
  assets-micro/
    *.png                   # small brand-colored icons + real logos
  mascot/
    node-<pose>.png          # 7 locked code-generated mascot poses
  hero/
    <name>-hero.mp4           # photoreal Gemini cinemagraph bookend shots
    <name>-hero-still.png      # the source still, kept for reference/reuse
  captions.ass / .json / .js  # generated by karaoke.py, DO NOT hand-edit
  sound-<variant>.json        # soundbed.py cue sheet
  build.py                    # the ffmpeg filter-graph assembly script
  ep001-visual.mp4             # silent render (build.py output)
  ep001-visual-audio.mp4        # final muxed render (soundbed.py output)
  delivery/
    <episode>-vX.Y-FINAL.mp4    # the actual posting-ready file, copied here
```

Start a new episode from `ai-agency/demos/_template/`.

## 2. Step-by-step build order

### A. Script the narration
Write `narration/narration.json`:
```json
{
  "engine": "edge", "voice": "en-US-AndrewMultilingualNeural", "rate": "+6%",
  "fps": 30, "total_seconds": 46,
  "cues": [
    {"id": 1, "at": 0.4, "window": [0, 4], "text": "..."},
    ...
  ]
}
```
**Acronym pronunciation rule:** if the script needs an acronym said
letter-by-letter (e.g. "CRM"), write it hyphenated in the script text
(`"C-R-M"`) so the TTS engine pronounces each letter. `karaoke.py` (see
step E) automatically collapses this back into a clean on-screen word — do
not hand-edit captions to "fix" this, the merge is automatic and general.

Generate VO with `reels/_kit/voice/narrate.py` (3 engines: sarvam, kokoro,
edge — see `reels/_kit/README.md` for exact voice IDs), or record and drop
in a real `vo.mp3` at the exact path.

**Silence-gap check — do this immediately, before building anything else:**
```bash
ffmpeg -i vo.mp3 -af "silencedetect=noise=-35dB:d=0.3" -f null - 2>&1 | grep -i silence
```
Every pause should be ~0.3-1.0s (natural speech pauses / scene-boundary
beats). Any gap noticeably longer (we found a 2.99s gap once, should have
been ~0.5s) is dead air and must be trimmed before building:
```bash
ffmpeg -y -i vo.mp3 -filter_complex \
"[0:a]atrim=0:<T0>,asetpts=PTS-STARTPTS[a];[0:a]atrim=<T1>:<END>,asetpts=PTS-STARTPTS[b];[a][b]concat=n=2:v=0:a=1[out]" \
-map "[out]" vo-trimmed.mp3
```
Pick `<T0>`/`<T1>` well inside the detected silent region (a few hundred ms
of buffer on each side) so no word gets clipped. **This changes the total
duration** — every downstream cue timestamp at or after the cut point must
shift by the same delta. Update `TOTAL` in `build.py`, every affected
`t0`/`t1`/`enable='between(...)'` after the cut, and `sound-*.json`'s
`total` + any `sfx`/`cuts` timestamps after the cut, all by the same delta.

**Overrun check — read `narrate.py`'s own console output, every single
time, before doing anything else.** It prints, per cue, the synthesized
line's actual duration and flags `<-- OVER N.NNs` whenever a cue's speech
runs past its own `window` end. This is not cosmetic — `narrate.py` lays
every cue onto the timeline at its fixed `"at"` timestamp regardless of how
long the PREVIOUS cue's real speech turned out to be. If cue N's actual
speech end time is later than cue N+1's `"at"`, the two cues' audio is
mixed (summed), not sequenced — both voices play simultaneously, sounding
garbled. This has happened twice on this system (case-file-002, hit twice
in one session; caught pre-emptively on ep-002). Symptom if missed until
final delivery: a viewer reports two lines "overlapping" or the VO
"sounding wrong" right at the overrun point.

**The fix — recompute timestamps, then rebuild from cache, never
re-synthesize:**
1. From the console output (or `report.json`, written alongside `vo.mp3`),
   get every cue's real `ends` time.
2. Recompute each cue's `"at"` sequentially: `at[i+1] = ends[i] + 0.2-0.3s`
   (a natural inter-sentence pause). Update `narration.json` with these
   corrected values — `window` should track `at` too, even though `window`
   is only used for the overrun *report*, not the actual audio layout.
3. **Do not re-run `narrate.py`** to pick up the new timestamps — it calls
   the TTS engine fresh for every cue, and even identical text can come
   back as a different take (different pacing, different micro-performance)
   on a second call. Re-synthesizing the whole file risks a perceptible
   tonality shift across lines the user already approved, on top of not
   even being necessary. Instead, `narrate.py` already cached every cue's
   individual clip at `narration/lines/cue_0N.wav` — rebuild `vo.mp3` from
   those exact same clips at the corrected timestamps:
   ```bash
   ffmpeg -y -i lines/cue_01.wav -i lines/cue_02.wav ... \
     -filter_complex \
     "[0:a]adelay=<at1_ms>|<at1_ms>[v0];[1:a]adelay=<at2_ms>|<at2_ms>[v1];...; \
      [v0][v1]...amix=inputs=<N>:normalize=0:dropout_transition=0, \
      atrim=0:<TOTAL>,apad=whole_dur=<TOTAL>, \
      loudnorm=I=-16:TP=-1.5:LRA=11[vo]" \
     -map "[vo]" -c:a libmp3lame -b:a 192k vo.mp3
   ```
   This is the exact `adelay`+`amix` recipe `narrate.py` itself uses
   internally (see its source) — replicate it by hand with the new `at`
   values instead of calling the script.
4. **Verify with `silencedetect` again afterward** (same command as above)
   — confirm a real, clean gap now exists at every former overrun point,
   and check the file's bitrate matches the original (`ffprobe -show_entries
   format=bit_rate`) — a hand-rolled `ffmpeg` re-encode without an explicit
   `-b:a` can silently drop to a much lower default bitrate (hit once: 192k
   → 64k).
5. If any visual scene-boundary in `build.py` was keyed to the old `"at"`
   values (e.g. a photoreal hero clip's fade-out timed to when a line
   *used* to end), update those too — the corrected audio timing should
   drive the visual timing, not the other way around.

### B. Real evidence mockups
Any "real UI" shot (CRM row, flow diagram, dashboard) is a hand-written
HTML file at 1080×1350 using the exact brand palette (see
`DESIGN_PHILOSOPHY.md`), screenshotted via a local `http.server` +
`opencli browser <profile> screenshot`, then cropped to the relevant region
with ffmpeg (`crop=W:H:X:Y`). Never use a flat pasted screenshot as the ONLY
treatment for more than ~3-4s on screen without at least a sequential
build-in (see Design Philosophy → "never show a flat screenshot").

**Dashboard-as-evidence (added ep-002):** beyond a one-off UI mockup for a
single transaction (a CRM row, one SMS thread), build a second evidence
card that shows the automation as an aggregate **product dashboard** — KPI
tiles, a small day-by-day bar chart, a "recent activity" feed, styled as a
real SaaS analytics page in the brand palette. This does real persuasive
work the single-transaction mockup can't: it makes the system look like an
operating product with a track record, not a one-time trick. Same HTML →
screenshot → crop pipeline as any other evidence card (see `ep-002-
missed-call-agent/evidence/dashboard.html` for the reference
implementation — KPI grid, CSS bar chart, activity rows, all just
div/flexbox, no chart library needed). Good placements: a brief crossfade
cutaway bridging the individual-case evidence beat into the aggregate-
result beat, or as the sole background for the result/counter beat itself.

### C. Micro-assets (icons/logos)
`reels/_kit/microassets/fetch_assets.py` — pulls generic icons (Iconify, no
key) and real brand logos (Logo.dev, needs `LOGO_DEV_PUBLISHABLE_KEY` in
`.env`) into ffmpeg-ready transparent PNGs, recolored to brand hex via a
spec JSON:
```bash
py -3 fetch_assets.py <spec.json> <outdir>
```
Real third-party logos (Gmail, HubSpot, n8n) are used verbatim in their own
brand colors — that's fine, it's nominative/identification use. Generic
icons (check, bell, arrow) get recolored to our palette.

### D. The mascot ("Node")
Two asset tiers, used for different jobs — see Design Philosophy for the
"why":
1. **Flat code-drawn poses** (`ai-agency/mascot/node.py`, Pillow) — 7 locked
   poses (`neutral, pointing, thinking, celebrating, working, idea,
   running`), pixel-perfect and free, used for small pop-ins during the
   flat UI/demo section of an episode.
   ```
   py -3 node.py <pose> <out.png> [--size 600]
   ```
2. **Photoreal Gemini hero shots** — used ONLY at the hook/CTA bookends, see
   `GEMINI_ASSET_AUTOMATION.md`.

**Mascot placement safe zone (hard rule):** never place a mascot pop-in
below ~y=1570 or within ~100px of the right edge on a 1080×1920 canvas —
that's where Reels/TikTok's own caption bar and like/comment/share icon
column sit and will visually clip it. Standard safe placement for a
bottom-right accent: `x≈670-780, y≈1080-1120`.

### E. Captions
```bash
py -3 reels/_kit/captions/karaoke.py <vo.mp3> <outdir> \
    --script narration.json --key-hex "#4E71FF" --ink-hex "#413333" --font "Inter"
```
Produces `captions.json` (word-level timing), `captions.ass` (burn-in
subtitle file), `captions.js`. **Ink color must match the current
background** — dark ink (`#413333`) on the light beige brand, would need
light ink on a dark background. Always regenerate captions after any VO
edit (trim, re-record) — never hand-patch the `.ass` file's timing.

### F. The build script (`build.py`)
This is the core of the pipeline — an ffmpeg `filter_complex` graph built
up in Python as a chain of string-appended filters. Study
`demos/ep-001-inbox-to-crm/build.py` directly; the pattern is:

1. **Base layer**: `color=c=<BEIGE>:s=1080x1920:d=<TOTAL>,drawgrid=...[bg]`
2. **`cur` variable discipline** — every single filter appended to the
   graph MUST take `{cur}` as its input and reassign `cur` to its own
   output label. This is not optional: ffmpeg's auto-linking will silently
   mis-wire the graph if a filter is appended without explicit chaining,
   producing either a frozen frame or an element that "bleeds" into every
   later scene forever (a real bug hit twice this project — see QC
   checklist item 3).
3. **Helper functions** (all reusable, copy verbatim into a new episode):
   - `ff_path(p)` — escapes Windows drive-letter colons for ffmpeg filter
     args (`D:\...` → `D\:/...`). Every path used inside a filter string
     needs this.
   - `add_input(path)` — registers a new looping still-image input.
   - `add_video_input(path)` — registers a real (non-looped) video clip
     input, timeline starting at t=0 of the whole render.
   - `badge_claim(label, line1, line2, color, t0, t1, y)` — the standard
     "small tracked-caps label + two-line bold claim" card treatment.
   - `hand_underline(...)` / `hand_box(...)` — self-drawing annotation
     strokes. **`hand_box` requires an explicit `t_off`** (upper time
     bound) or the annotation never turns off and bleeds into later scenes.
   - `pop_in(idx, x, y, size, t0, t1, label)` — fade+drop-in micro-asset.
   - `node(pose, x, y, size, t0, t1, label)` — wraps `pop_in` for a mascot
     pose PNG.
   - `hero_bg(path, t0, t1, fade_out)` — full-bleed photoreal video
     background for a bookend beat; auto-fades to the flat base at `t1`.
   - `proof_flash(label_text, t0, dur, color, label)` — a tiny evidence
     chip flash (the "Proof Layer" — see Design Philosophy).
   - `pinned_strip(text, t0, t1)` (added ep-002) — a small badge that stays
     mounted across a LONG window (e.g. the entire hook-through-build
     span, cues 1-3), unlike `badge_claim`'s cards which swap text every
     cue. Modeled on a competitor-reverse-engineered pattern (see
     `SCRIPT_FORMULA.md`'s "persistent pinned headline" note): keeping one
     claim visible continuously reinforces the hook's promise instead of
     letting it disappear after 4 seconds. Implement as a single
     `drawbox`+`drawtext` pair whose `enable='between(t,{t0},{t1})'` spans
     the full multi-cue window, composited once, early in the filter chain
     so later per-cue cards layer on top of it without conflict.
4. **Cue-by-cue timeline** — one block per narration cue, drawing cards,
   evidence overlays, pop-ins, and annotations at their exact timestamps.
5. **Human-touch pass** — camera drift + grain. **Scope this ONLY to
   photoreal hero segments**, never to flat UI text/cards (see Design
   Philosophy → "camera must have a reason"). Gate the drift amplitude to
   zero smoothly at the same point the hero clip itself fades out, so
   framing settles with no snap:
   ```python
   GATE = "if(lt(t,T_FADE_START),1,if(lt(t,T_FADE_END),(T_FADE_END-t)/(T_FADE_END-T_FADE_START),0))"
   ```
6. **Caption burn-in** — `subtitles=<captions.ass>:fontsdir=<google fonts dir>`
   as the very last filter.
7. Assemble the final `ffmpeg` command (`-filter_complex`, `-map "[final]"`,
   `-t TOTAL`, `-r 30`, `libx264 -crf 20 -pix_fmt yuv420p`) and run it.

Run: `py -3 build.py` → produces `<episode>-visual.mp4` (silent).

### G. Sound design
`reels/_kit/sound/soundbed.py` — cue-on-every-cut sound design + final mux.
Write a `sound-<variant>.json`:
```json
{
  "video": "ep001-visual.mp4", "vo": "narration/vo.mp3",
  "bed": "<music bed path>", "bed_trim_start": 24, "bed_gain_db": -20,
  "room_tone": true, "room_tone_db": -36, "total": 43.56,
  "cuts": [], "sfx": [[0.3, "transition/transition-soft", -19], ...]
}
```
`"cuts"` auto-assign a matching SFX by kind (cold/cut/slide/flip/stamp/
meter/pen/warp — no cut without a sound). `"sfx"` are one-off accent sounds
at specific timestamps. Run:
```bash
py -3 reels/_kit/sound/soundbed.py sound-<variant>.json
```
Produces `<episode>-visual-audio.mp4` = VO + bed (ducked) + room tone + all
SFX, normalized to -14 LUFS.

### H. QC
Run the full checklist in `QC_CHECKLIST.md` before calling it done. At
minimum: silence-gap check on the FINAL muxed audio, frame-grab every cue
boundary and eyeball it, verify mascot/text never overlaps or clips into an
unsafe zone.

### I. Delivery
Copy the final muxed file into `<episode>/delivery/<episode>-vX.Y-FINAL.mp4`
and hand that path to the user. Never call the raw `build.py`/`soundbed.py`
output paths the "final" deliverable — always land on a clearly-versioned
copy in `delivery/`.

## 3. Common bugs and their fixes (read before debugging blind)

| Symptom | Cause | Fix |
|---|---|---|
| Frozen single-frame video, or an element bleeding into every later scene | A filter appended without chaining `{cur}`→new label, or `hand_box` missing `t_off` | Every filter must read `{cur}` and reassign `cur`; always pass `t_off` to `hand_box` |
| ffmpeg "Invalid argument" / filtergraph parse error on Windows | Unescaped `:` in a `D:\...` path inside a filter string | Always pass paths through `ff_path()` |
| Duplicate on-screen label (e.g. "THE BUILD" drawn twice) | A `drawtext` label added in `build.py` when the evidence PNG already has that label baked into the HTML mockup | Check the evidence HTML before adding a redundant caption layer |
| Whole video "shakes"/feels cheap despite sharp assets | Whole-frame Ken-Burns pan + grain applied uniformly over flat vector UI text | Scope camera drift/grain ONLY to real photographic/rendered content; flat cards stay pixel-static |
| Caption shows "C -R -M" with visible hyphens | Script wrote an acronym hyphenated for TTS pronunciation, and whisper transcribed it as separate letter-tokens verbatim | Fixed generically in `karaoke.py` — merges runs of single-letter tokens into one clean display word |
| Mascot or text gets visually clipped when previewed as an actual Reel/TikTok | Placed inside the platform's own bottom-caption-bar / right-icon-column zone | Keep key content within `y < ~1570` and away from the rightmost ~100px |
| Cutaway shows the wrong moment of a generated video clip | A short cutaway cut from a longer generated clip only shows its opening frames | Add a `seek` (`-ss`) offset before the video input so the cutaway lands on the resolved/interesting part |
| Real assets composited "under" active card text muddy both | Cutaway/asset placed in a busy moment instead of a clean gap | Only flash real assets in a gap where no card text is simultaneously active |
| Gemini web automation silently does nothing (`Image never appeared`) | The Send button click didn't register (Angular timing), or you've hit the account's image-generation rate limit, or the tab reset to `about:blank` | See `GEMINI_ASSET_AUTOMATION.md` §"Flakiness playbook" |
| Two VO lines audibly overlap/garble at one point in the final mix | A cue's real synthesized speech ran longer than its `window`, into the next cue's fixed `"at"` start — `narrate.py` mixes cues by fixed timestamp, not sequentially | See §A "Overrun check" above — recompute `at` values, rebuild `vo.mp3` from cached `lines/cue_0N.wav`, never re-synthesize the whole file |
| Gemini returns a completely unrelated image (e.g. an old pitch deck) instead of the requested prompt | `gemini.google.com/app` resumed the last active conversation instead of starting blank — client-side routing doesn't guarantee a fresh chat | Explicitly click the "New chat" control before sending the first prompt — see `GEMINI_ASSET_AUTOMATION.md` §"Guaranteeing a truly fresh chat" |
| A hand-rebuilt `vo.mp3` (or any manual ffmpeg re-encode) sounds thin/compressed | Re-encoding without an explicit `-b:a` silently falls back to a low default bitrate | Always pass the original file's bitrate explicitly (check with `ffprobe -show_entries format=bit_rate` first) |
| Assets mapped to wrong cues / single-frame overlays swapped | Separate input lists (e.g. `inputs_evidence` vs `extra_inputs`) caused index mismatch between filter labels `[N:v]` and command-line `-i` flags | Keep a single unified `inputs = []` list where every `add_input` / `add_video_input` appends and returns `len(inputs) - 1` |
| Text containing `%` (e.g. "78% GO WITH") silently vanishes from screen | ffmpeg `drawtext` evaluates `%` as a format specifier, and Python f-strings parse `%%` before ffmpeg receives it | Add `:expansion=none:` to the `drawtext` filter for literal text, or escape as `\\\\%` |
| Missing glyph box (rectangle) rendered on screen | Emojis (e.g. ⚡) passed into `drawtext` with Arial font | Stick to standard typography or pop in real PNG micro-assets via `pop_in` |
| ffmpeg `Error when evaluating the expression 'or(...)' for enable` | `or()` is an unsupported function in ffmpeg arithmetic evaluation | Use `+` for logical OR (`lte(t,5.3)+gte(t,39.51)`) or conditional `if()` |
